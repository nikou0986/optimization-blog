Why Linear Programming Is Not Enough

In the previous post, we introduced Linear Programming (LP), where decision variables are continuous. This works well when the decision represents a divisible quantity, such as the amount of products to manufacture, electricity to generate, or goods to transport.

However, many real-world optimization problems involve discrete decisions rather than continuous quantities.

For example:

  • Should a new warehouse be built?
  • Which projects should receive funding?
  • Which employee should be assigned to a task?
  • What is the shortest route that visits every customer exactly once?

These decisions cannot take fractional values. A warehouse cannot be built halfway, an employee cannot perform \(0.4\) of a job, and a project cannot be selected \(1.7\) times.

If these problems were modeled using Linear Programming, the optimal solution might contain fractional values that are mathematically feasible but practically meaningless.

To model such problems, we require decision variables to take integer values. This leads to Integer Programming (IP).

Integer Programming is useful when the decision is indivisible. The decision variable must represent a whole number or a yes-or-no choice.

Integer vs. Binary Decision Variables

Integer decision variables generally fall into two categories.

General Integer Variables

Some decisions represent discrete quantities, where only whole numbers are meaningful.

Examples include:

  • Number of buses to purchase
  • Number of workers to hire
  • Number of machines to install

These variables satisfy

\[ x\in\mathbb{Z}, \]

where \(\mathbb{Z}\) denotes the set of integers.

Binary Variables

Many optimization problems involve yes-or-no decisions.

Examples include:

  • Should this warehouse be opened?
  • Should this project be selected?
  • Should worker \(i\) be assigned to job \(j\)?

These decisions are naturally modeled using binary variables,

\[ x\in\{0,1\}, \]

where

  • \(1\) indicates Yes or selected,
  • \(0\) indicates No or not selected.

Because binary variables are integers restricted to two possible values, Binary Integer Programming (BIP) is a special case of Integer Programming.

Common Integer Programming Problem Types

Many real-world optimization problems can be represented using a small number of classical Integer Programming formulations.

Problem Type Main Decision Typical Variable
Knapsack Which items should be selected? Binary
Assignment Which resource should be assigned to which task? Binary
Set Covering Which sets should be selected to cover all requirements? Binary
Set Partitioning Which sets should be selected so every element is covered exactly once? Binary
Facility Location Which facilities should be opened? Binary + continuous

Knapsack Problem

The Knapsack Problem is one of the simplest and most important Integer Programming models.

Suppose we have a limited budget, capacity, or resource. We must decide which items to select in order to maximize total value without exceeding the limit.

The decision variable is

\[ x_i= \begin{cases} 1, & \text{if item } i \text{ is selected},\\ 0, & \text{otherwise}. \end{cases} \]

A basic knapsack model is

\[ \max \sum_{i\in I} v_i x_i \]

subject to

\[ \sum_{i\in I} w_i x_i \le C, \]

\[ x_i\in\{0,1\}, \qquad \forall i\in I. \]

where

  • \(v_i\) is the value of item \(i\),
  • \(w_i\) is the weight or resource requirement of item \(i\),
  • \(C\) is the total capacity.

The knapsack problem is about selection under a limit: choose the best combination of items without exceeding capacity.

Assignment Problem

The Assignment Problem is a special case of the transportation problem, but it is usually formulated as a binary Integer Programming problem.

In an assignment problem, each source has a supply of one unit and each destination has a demand of one unit. For example, each worker can be assigned to one job, and each job needs exactly one worker.

The decision variable is

\[ x_{ij}= \begin{cases} 1, & \text{if worker } i \text{ is assigned to job } j,\\ 0, & \text{otherwise}. \end{cases} \]

The objective is often to minimize assignment cost:

\[ \min \sum_{i\in I}\sum_{j\in J} c_{ij}x_{ij}. \]

Each worker is assigned to exactly one job:

\[ \sum_{j\in J}x_{ij}=1, \qquad \forall i\in I. \]

Each job receives exactly one worker:

\[ \sum_{i\in I}x_{ij}=1, \qquad \forall j\in J. \]

Finally,

\[ x_{ij}\in\{0,1\}. \]

The assignment problem can be viewed as a transportation problem where every supply and every demand equals \(1\). The binary variable ensures that the assignment is either made or not made.

Set Covering Problem

The Set Covering Problem asks:

What is the minimum-cost collection of sets that covers all required elements?

A common example is facility coverage. Suppose we need to choose fire stations so that every neighborhood is covered by at least one station.

Let

\[ x_j= \begin{cases} 1, & \text{if set } j \text{ is selected},\\ 0, & \text{otherwise}. \end{cases} \]

The objective is

\[ \min \sum_{j\in J} c_jx_j. \]

Each requirement must be covered at least once:

\[ \sum_{j\in J_i}x_j\ge 1, \qquad \forall i\in I. \]

where \(J_i\) is the set of options that can cover requirement \(i\).

Set covering means at least one selected option must cover each requirement.

Set Partitioning Problem

The Set Partitioning Problem is similar to set covering, but it is stricter.

Instead of requiring each element to be covered at least once, set partitioning requires each element to be covered exactly once.

The model is

\[ \min \sum_{j\in J} c_jx_j \]

subject to

\[ \sum_{j\in J_i}x_j=1, \qquad \forall i\in I, \]

\[ x_j\in\{0,1\}. \]

Set covering uses \(\ge 1\), while set partitioning uses \(=1\).

  • Set covering: every requirement must be covered at least once.
  • Set partitioning: every requirement must be covered exactly once.

Set partitioning is commonly used in problems such as airline crew scheduling, vehicle routing, and task assignment, where each flight, customer, or task must be assigned to exactly one feasible route or schedule.

Traveling Salesman Problem

The Traveling Salesman Problem (TSP) asks:

What is the shortest route that visits every city exactly once and returns to the starting city?

The TSP is a classic combinatorial optimization problem. It is not simply a shortest path problem, because the route must visit all cities exactly once before returning to the starting point.

Let

\[ x_{ij}= \begin{cases} 1, & \text{if the route travels directly from city } i \text{ to city } j,\\ 0, & \text{otherwise}. \end{cases} \]

The objective is

\[ \min \sum_{i\in N}\sum_{j\in N} c_{ij}x_{ij}, \]

where \(c_{ij}\) is the distance or travel cost from city \(i\) to city \(j\).

Each city must be entered exactly once:

\[ \sum_{i\in N}x_{ij}=1, \qquad \forall j\in N. \]

Each city must be left exactly once:

\[ \sum_{j\in N}x_{ij}=1, \qquad \forall i\in N. \]

Additional constraints are needed to eliminate subtours, which are smaller disconnected cycles that do not visit every city in one complete tour.

The TSP is not the same as the shortest path problem. The shortest path problem finds the cheapest path from one node to another, while the TSP finds the cheapest tour that visits every node exactly once.

Scheduling Problems

Scheduling problems ask:

Which jobs should be performed, when should they be performed, and in what order?

Many scheduling problems are modeled as Integer Programming or Mixed Integer Programming problems because they involve discrete decisions.

For example,

\[ x_{it}= \begin{cases} 1, & \text{if job } i \text{ starts at time } t,\\ 0, & \text{otherwise}. \end{cases} \]

Scheduling can also be connected to set covering or set partitioning. For example, in workforce scheduling, each feasible work pattern can be treated as a set of shifts covered by one employee. The optimization then chooses a collection of work patterns so that all required shifts are covered.

Scheduling is an application area, while set covering and set partitioning are mathematical formulations. Some scheduling problems can be formulated as set covering or set partitioning problems.

Summary

Integer Programming is used when decision variables must represent whole numbers or yes-or-no choices. It is especially useful for problems involving selection, assignment, routing, facility location, and scheduling.

Model Core Idea
Knapsack Select the best items under a capacity limit
Assignment Match resources to tasks one-to-one
Set Covering Cover every requirement at least once
Set Partitioning Cover every requirement exactly once
Traveling Salesman Problem Find the shortest tour visiting every city once
Scheduling Decide timing, ordering, or resource assignment

The main difference between LP and IP is not the objective function or constraint structure. Both can still be linear. The key difference is the domain of the decision variables.

  • LP allows continuous decision variables.
  • IP restricts some or all decision variables to integers.
  • Binary IP restricts variables to \(0\) or \(1\).

This makes Integer Programming especially powerful for modeling real-world decisions that are discrete, indivisible, or logical.
